本カリキュラムでは、個人の生産性向上にとどまらず、**組織全体として安全かつ持続可能に GitHub Copilot および Codex/自律エージェントを運用するためのガバナンス設計・標準化・ROI測定** のフレームワークを習得します。

---

## 🎯 学習ゴール (Learning Objectives)
1. **指示書設定の Single Source of Truth (SSOT)**: ツールごとの設定分散・二重管理を防ぐアーキテクチャを確立できる。
2. **安全な承認ポリシーとコマンド実行制御**: 破壊的操作を防ぐ Approval Mode、サンドボックス化、シークレット漏洩防止策を標準化できる。
3. **プロンプト資産の組織的共有運用**: 属人化を排除し、チーム共通のプロンプト・エージェントを Git で継続的改善する仕組みを作れる。
4. **導入効果の定量的・定性的測定**: PRマージ時間、コードカバレッジ、受容率（Acceptance Rate）、開発者体験（DX）のKPIを設計できる。

## 🛠 ガバナンス実践フレームワーク (Framework & Operations)

### 1. 指示書二重管理防止の共通化パターン (SSOT)
Copilot（VS Code/Cursor）と 自律エージェントCLI（Codex, Claude Code, Antigravity等）で、別々にプロンプトを保守すると設定の乖離が発生します。

```text
               ┌───────────────────────────────┐
               │    リポジトリ共通仕様の核     │
               │           AGENTS.md           │
               └──────────────┬────────────────┘
                              │
               ┌──────────────┴───────────────┐
               │  シンボリックリンク or 参照  │
               ▼                              ▼
┌──────────────────────────────┐ ┌──────────────────────────────┐
│  .github/copilot-instructions │ │  Codex / Claude / Agent CLI  │
│      (Copilot IDE 拡張)      │ │   (自律型ターミナルエージェント) │
└──────────────────────────────┘ └──────────────────────────────┘
```

#### 実装パターン:
- **ルール1**: 原則となるビルドコマンド、テストコマンド、コーディング規約は `AGENTS.md` にのみ定義する。
- **ルール2**: `.github/copilot-instructions.md` では `AGENTS.md` を参照・補完する形式とする（「詳細はリポジトリルートの AGENTS.md に従ってください」と明記）。
- **CIでの整合性検証**: CIパイプラインで指示書間の矛盾や古いコマンドの残存を自動検知するスクリプトを導入する。

---

### 2. コマンド実行制限と承認ポリシー（Approval Policy）
自律エージェントがターミナルで任意のシェルコマンドを実行できる場合、重大なリスク（データ損失、不正送信、破壊的リセット）が存在します。

#### 推奨運用ポリシー:
| 操作レベル | 例 | 承認設定 (Approval Policy) |
| :--- | :--- | :--- |
| **Level 1: 読み取り専用** | `git status`, `git diff`, ファイル閲覧 | **常時自動許可 (Auto-approve)** |
| **Level 2: 安全な検証実行** | `npm test`, `npm run typecheck`, `npm run lint` | **常時自動許可 (Auto-approve)** |
| **Level 3: ローカルファイル変更** | ソースコード編集、新規ファイル作成 | **差分確認後に承認、またはGitコミット前レビュー** |
| **Level 4: 外部通信・破壊的操作** | `git push -f`, `rm -rf`, 外部URLへの `curl`, DBマイグレーション | **明示的ユーザー承認必須 (Always Prompt / Deny)** |

#### シークレット漏洩対策:
- `gitleaks` や `trufflehog` などの Pre-commit フックを導入し、AIが生成したコードやプロンプト履歴にトークンが含まれていないかをコミット前に自動スキャンする。

---

### 3. プロンプト資産のチーム共有運用
「プロンプトの上手い人だけが恩恵を受ける」属人化を防ぐため、プロンプトをコードと同様にGit管理します。

1. **`.github/prompts/` の活用**:
   - 定型タスク（Issueからの修正、PR説明文生成、マイグレーション等）をMarkdownファイル化し、チーム全体でレビュー・バージョン管理する。
2. **Prompt PR フロー**:
   - 「AIがこの指示だと勘違いしやすい」「新しいテストコマンドが追加された」場合、プロンプト改善のPRを作成し、チームでマージする。

---

### 4. 導入効果測定（ROI / KPI メトリクス）
経営陣・ステークホルダーに導入効果を可視化するための指標セットです。

```text
                    ┌─────────────────────────┐
                    │    AI導入 総合評価軸    │
                    └────────────┬────────────┘
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
【開発生産性 (Speed)】    【コード品質 (Quality)】  【開発者体験 (DX)】
・PRリードタイムの短縮    ・テストカバレッジ率      ・定性アンケート(満足度)
・チケット消化速度        ・本番バグ混入率の推移    ・認知的負荷の軽減度
・Copilot 受容率(>30%)   ・CIビルド成功率          ・オンボーディング期間
```

- **GitHub Copilot Metrics API**:
  - `acceptance_rate`（コード提案受容率: 業界平均25〜35%をターゲット）
  - `active_users`（アクティブ利用率）
- **DORA メトリクス連携**:
  - デプロイ頻度（Deployment Frequency）
  - 変更リードタイム（Lead Time for Changes）
